# 小型云端元数据热路径与缓存签名事故（2026-08-24）

状态：长期硬约束 / 跨程序可复用。

## 1. 事故背景

“我的规则仓库”3.5.6-rc6 已把多版本程序 `channels.json` 从首页 N+1 预取改成详情按需加载，功能正确后实机仍出现：点击程序查看版本信息明显等待。

根因不是 JSON 大，而是错误复用了核心发布文件的重容灾 transport：GitHub API → Raw → jsDelivr → WebRaw，单路可达 20 秒。几 KB 的详情元数据因此拥有了最坏数十秒的交互延迟。

## 2. 固定原则：传输策略必须按交互热度分级

核心 Release/Bootstrap/不可变模块可以使用高可靠多镜像重容灾；详情页的小型元数据不得默认复用同一慢链。

交互热路径推荐：

```text
持久成功缓存
→ 快速 CDN（短超时）
→ 高新鲜度 API（短超时）
→ WebRaw/Raw 短超时兜底
→ 最后成功缓存/可见错误
```

所有单路超时必须有明确上限，不能把 4×20s 的最坏情况直接暴露给用户点击。

## 3. 导航不得被网络阻塞

点击详情的产品合同应为：

```text
立即进入详情骨架
→ 显示“加载中”
→ 仅加载当前对象的子元数据
→ 成功后局部/整页刷新
```

禁止：

```text
点击卡片
→ 同步等待远端 metadata
→ 请求完成后才进入详情
```

网络失败也必须保留可返回、可重试的详情页，不允许让用户误以为点击失效。

## 4. 缓存失效必须使用对象级语义签名

根 manifest revision 变化通常可能只是其它程序更新。用全局 revision 失效所有程序的版本中心缓存会制造缓存雪崩。

推荐签名：

```text
item.id
+ item.channelsPath
+ item.version / channel summary
+ item.updatedAt
```

只有目标程序自己的摘要变化，才重新加载它的 `channels.json`。

## 5. CDN @main 必须做新鲜度校验

CDN 快路径可能存在传播延迟。不能因为 CDN 返回了结构合法 JSON 就直接信任。

父目录应保留 Stable/Test/Local 轻量摘要，子 metadata 返回后进行语义对照；不匹配时视为 CDN 滞后并回退高新鲜度源。

但摘要与真实版本不是永远完全相等。允许合法派生关系，例如：

```text
父摘要 Local 1.8.2
子版本 1.8.2-local.1
```

应视为兼容；而：

```text
Test 1.9.0-test.5
Test 1.9.0-test.6
```

必须视为不同版本，不能用前缀规则误放行。

## 6. 缓存成功仍需语义有效

延续 `INCIDENT_CLOUD_CATALOG_HOT_PATH_AND_UPDATE_INDEX_20260824.md`：

- 空数组不是成功；
- 结构合法但版本摘要滞后也不是成功；
- 新失败数据不得覆盖最后成功缓存；
- 命中有效缓存时应直接进入详情，不重复联网。

## 7. 本次修复线

- RC6 / Single Workspace 14.5：通用 channel-group 详情按需加载恢复功能正确性。
- RC7 / 14.6：Fast Version Center，缓存优先、CDN-first、短超时多源回退、程序级缓存签名、先渲染后加载。
- RC8 / 14.6.1：修复父目录简化基线版本与真实 Local/派生版本的兼容校验边界。

## 8. 发布门禁

涉及远端小型 metadata 的改动必须实机验证：

1. 首次进入详情不被网络请求阻塞；
2. 首次加载时间有明确上限；
3. 第二次进入命中缓存近似即时；
4. 其它程序发布不会让全部缓存失效；
5. CDN 旧数据可识别并回退；
6. 合法派生版本不会被误判为滞后；
7. 网络全部失败仍有可见详情/错误/重试路径；
8. 首页不能因为性能优化重新引入 N+1 子资源预取。
