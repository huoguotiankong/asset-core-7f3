# 海阔小程序开发指南补充：搜索 / 输入框精简标准

日期：2026-09-22  
适用范围：`asset-core-7f3@main` 内全部海阔小程序，新开发与后续维护统一执行。

## 1. 核心原则

搜索框、链接输入框、口令输入框的首要任务是 **让用户输入**，不是承担说明书职责。

默认禁止在输入区域塞入长段提示、协议列表、功能说明、操作教程或调试信息。输入框必须保持短、干净、一眼可扫。

## 2. 默认文案规范

优先使用：

- 搜索内容：`搜索` / `关键词`
- 搜索影片：`搜索影片`
- 搜索漫画：`搜索漫画`
- 网盘搜索：`搜索文件`
- 磁链/下载：`粘贴链接`
- 口令：`输入口令`
- 验证码：`验证码`

除非业务名称本身必须出现，中文提示建议控制在 **2～6 个汉字**；通常不要超过 **8 个汉字**。

禁止类似：

- `请输入影片名称、演员、番号或关键词进行搜索`
- `粘贴 magnet / ed2k / HTTP(S) 链接`
- `输入115分享链接、磁力链接、文件名关键词...`

## 3. 说明信息放在哪里

只有用户真的需要时再出现：

1. 输入格式错误后，用 `toast://` 简短说明；
2. 页面存在多个不明显模式时，用独立帮助/说明按钮；
3. 技术参数放长按菜单、诊断页或高级设置；
4. 不要在输入框下默认堆协议名、CID、内部模式、完整 hash、endpoint 等开发信息。

## 4. 信息层级

正常页面默认只显示：

`用户任务 → 核心结果 → 必要状态`

技术信息统一降级为：

`长按 / 详情 / 诊断 / 错误时按需显示`

例如离线任务列表默认显示：

`任务名 + 完成/下载状态 + 大小/进度`

不默认显示：

`info_hash / CID / hiker-cache / 内部 route / API 参数`

## 5. 修改策略

本规范从 2026-09-22 起作为全项目 UI 基线。

- 新程序：直接按本规范设计；
- 正在开发的 Test/Candidate：下一轮 UI 修改立即应用；
- 已验证 Stable：禁止为了统一样式一次性批量重写，等该程序下一次正常优化时顺带收敛，或先在 Test/Candidate 验证；
- 用户实机截图发现输入框信息密度过高时，优先做纯 UI 修复，不连带重构稳定协议链。

## 6. 首个实机案例

`115.简 1.2.1-test.13` 实机截图显示，输入框文案 `粘贴 magnet / ed2k / HTTP(S) 链接` 过长，并同时暴露 CID / hiker-cache / info_hash，明显干扰主任务。

`1.2.1-test.14` 按本规范修正：

- 输入框改为 `粘贴链接`；
- CID / 内部模式默认隐藏；
- info_hash 从列表移至长按操作；
- 页面标题缩短；
- 不改变离线协议与外部磁链安全链。
