# 海阔网页登录 Cookie 容器与私有缓存串号事故（2026-08-23）

状态：长期硬约束 / 跨程序适用。

## 1. 事故现象

Pornhub Test2/Test3 在官方网页登录后，小程序能够显示“登录成功”，但账号订阅、历史、收藏等私有内容与用户实际网页账号不一致。此前还出现过同步后用户名变化的问题。

Test3 已修复“从首页普通 `/users/<name>` 链接猜用户名”的明显错误，但实机继续证明：**用户名正确不代表原生请求真正处于同一账号会话。**

## 2. 根因

本次暴露的是两个独立问题叠加：

### A. 浏览器容器与 `getCookie()` 的会话来源必须一致

网页登录如果通过与海阔 X5 Cookie 容器不一致的入口完成，例如把 `web://` 当作必然与 `getCookie(url)` 共用 Cookie，就可能出现：

```text
网页里看到账号 A 已登录
↓
小程序 getCookie() 读到另一套/旧的 Cookie
↓
原生请求拿到非账号 A 的会话或匿名/残留状态
```

因此凡是后续原生协议依赖 `getCookie(url)`，登录流程必须优先使用与它明确共享会话的 X5 容器，例如：

```text
x5://<login-url>
```

或经过实机确认的全尺寸 `x5_webview_single`。

不得在没有实机证据时假设 `web://`、系统外部浏览器、X5、WebView、原生 `fetch` 自动共享同一 Cookie Store。

### B. 私有 HTML/API 缓存必须带账号会话指纹

公开页面可以按 URL 缓存；账号私有页面不能只按 URL 缓存：

```text
/auth page URL → cached HTML
```

否则账号 A 的：
- 推荐
- Feed
- 历史
- 收藏
- 订阅
- 私人片单

可能在切换到账号 B 后继续被旧缓存返回。

私有缓存至少需要：

```text
cacheKey = auth-session-fingerprint + URL + request-variant
```

会话指纹可由 Cookie/Token 的不可逆 hash + 长度/版本组成，不记录明文凭据。

账号重新同步、退出、Token refresh、Cookie 变化时，旧私有缓存必须自然失效或被显式清理。

## 3. 账号功能验收不能只看“登录成功”

账号链至少验证：

```text
网页登录看到的当前账号
= 原生身份页识别账号
= 原生历史内容
= 原生收藏内容
= 原生订阅内容
```

只验证用户名/头像，不能证明私有数据会话正确。

若任一私有列表与官方网页不一致，应优先排查：

1. 登录浏览器与 `getCookie()` 是否同容器。
2. 原生请求是否每次使用当前 live Cookie/Token，而不是旧保存值。
3. 私有缓存是否按账号会话隔离。
4. Parser 是否把推荐侧栏、热门作者等公共区域混进私有主列表。
5. 用户名路径是否只是展示参数，而真正授权仍来自 Cookie/Token。

## 4. 私有页面 Parser 必须限定业务容器

账号页尤其禁止“整页扫描所有视频/用户链接”。

例如订阅页可能同时包含：
- 我的订阅
- 推荐关注
- 热门演员
- 导航头像
- 页脚链接

正确策略：

```text
先定位 subscriptions / userLink / 主列表容器
→ 再解析人物实体
→ 无可靠容器宁可空状态/官方页兜底
→ 禁止把侧栏推荐伪装成用户订阅
```

历史/收藏同理，应优先解析主 `videoblock`/业务列表区域。

## 5. 登录/退出的永久规则

- 不保存账号密码。
- 登录用官方站点页面完成验证码/二次验证。
- 原生同步前必须用一个账号专属页面验证当前 Cookie/Token。
- 同步新会话前清掉旧身份显示字段。
- 退出小程序会话必须清掉本程序保存的 Cookie/Token/用户名/头像/身份来源/会话指纹。
- 是否清除官方浏览器 Cookie必须明确告知用户；默认不要越权删除。

## 6. Pornhub Test4 修复记录

Pornhub `0.1.0-test.4 / Build10104`：

- 登录入口改为 `x5://` 全屏官方登录，与 `getCookie(base)` 使用同一 X5 会话语义。
- 原生私有请求优先读取当前 live X5 Cookie。
- 私有页面缓存 key 增加 Cookie 指纹，切换账号不再复用另一账号的旧 HTML。
- `/user/security` 继续作为身份/登录验证页。
- 账号视频优先解析主 `videoblock`；订阅只接受 `subscriptions/userLink` 范围实体，避免推荐演员污染。
- 用户名仍只用于必须包含 `/users/<name>` 的路径；它不再被视为“账号会话正确”的充分证据。

## 7. 发布前固定回归

任何带网页登录 → 原生账号功能的小程序，发布前必须做：

```text
账号 A 登录
→ 检查身份/历史/收藏/订阅
→ 退出小程序会话
→ 账号 B 登录
→ 再检查身份/历史/收藏/订阅
```

若 B 页面出现 A 的任何私有列表条目，直接判定为发布阻断。
