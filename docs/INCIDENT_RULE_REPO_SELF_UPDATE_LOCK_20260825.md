# INCIDENT · 规则仓测试版自更新被硬编码 selfMeta 锁死 · 2026-08-25

## 现象
- 云端已发布更高的“我的规则仓库·测试版”，但测试仓自身版本中心仍显示旧 RC。
- 其它小程序的新 Test 可以通过目录刷新看到，规则仓自己的 Test 却看不到。
- 用户只能从 Stable“我的规则仓库”导入新测试仓，因此 Stable 无法安全晋级，否则会失去独立救援跳板。

## 根因
- 版本目录刷新模块为了避免 self 信息陈旧，在保存目录时把 `rule-repo` 条目强制改为当前补丁内硬编码版本。
- 后续补丁又继续对 `fastChannelCache(rule-repo)` 写死当前版本。
- 这种“当前版本纠偏”只能修本版显示，不能作为长期更新机制；它会主动覆盖未来更高版本，形成自更新锁。

## 禁止做法
1. 禁止在长期版本目录刷新器中用 `SELF_VERSION/SELF_BUILD` 无条件覆盖云端 `rule-repo` 条目。
2. 禁止把“当前运行身份”和“可用最新版本”混成同一个 selfMeta。
3. 禁止在测试仓无法独立发现下一测试版时晋级 Stable；Stable 必须保留为救援基线。
4. 禁止用整个共享 `manifest/registry/channel_catalog` 作为规则仓自更新的唯一真相。

## 正确模式
- 当前运行身份：由本地 Runtime/Shell 固定，只表示“我是谁”。
- 最新可用版本：由小型独立更新源 `apps/tools/rule-repo/channels.json` 提供。
- 主动检查：三镜像短超时读取更新源，按 Test Build 最大值选择最新结果。
- 正常启动：只读本地缓存，不联网。
- 当前运行 Build 只能作为最低可信保底；不得覆盖更新源中更高 Build。
- 发布 Stable 前必须做 N→N+1 自更新闭环：旧 Test 从测试仓内部发现并升级下一 Test。

## 回归门禁
- RC28 从 Stable 最后一次安装。
- RC28 自身详情显示 RC28，不回退 RC26。
- 发布 RC29 探针后，RC28 仅通过测试仓自身“检查版本”看到 RC29。
- RC28/RC29 在测试仓内部完成覆盖升级后，才解除 Stable 晋级禁令。
