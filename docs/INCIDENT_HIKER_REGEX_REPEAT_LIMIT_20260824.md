# 海阔 / Rhino 正则重复量词 50000 上限事故

日期：2026-08-24  
来源：18AV Test3 → Test4 实机回归

## 实机现象
18AV Test3 导入后首页尚未进入业务请求就直接报错：

```text
模块 core 全部镜像加载失败：
1:最大值50000太大 |
2:最大值50000太大 |
3:最大值50000太大
```

三个镜像同时出现完全相同错误，容易被误判为：
- core.js 文件超过 50KB；
- CDN/Raw 下载失败；
- Remote Manager 限制模块体积。

## 实际根因
GitHub 实际回读：
- `core.js` 仅 21690 bytes；
- `runtime.js` 仅 17510 bytes。

真正问题位于 Test3 漫画/写真脚本图片解析：

```js
/\b(?:Large_cgurl|...)\b\s*=\s*\[([\s\S]{0,250000}?)\]/ig
```

海阔当前 JavaScript / Rhino 正则实现对重复量词的最大上限为 50000。`{0,250000}` 在模块执行时即无法编译，因此 `require()` 抛错；Remote Manager 只是把模块执行异常包装成“模块全部镜像加载失败”。

## 固定规则
1. 海阔规则代码禁止使用超过 50000 的正则重复上限：

```text
{0,50001}
{1,100000}
{0,250000}
```

都属于禁用写法。

2. 大块 HTML / JavaScript 区域优先使用：

```js
[\s\S]*?
```

并依靠明确的后续边界、业务字段、数组闭合符、DOM 范围或字符串截断控制扫描范围，而不是用超大 `{0,N}` 量词。

3. 如果确实需要硬上限，应保持显著低于 50000，并优先先 `substring()` / `context()` 截取局部文本，再对局部文本做正则。

4. 当 `require()` 报“三个镜像完全相同的语法/运行异常”时，不要先判断网络；先检查模块是否在 eval/编译阶段失败。

5. 判断“模块是否过大”必须回读 GitHub 文件真实 byte size，不能仅根据错误文本猜测。

## 18AV 修复
- Test3 Release 保持不可变。
- Test4 使用独立 Hotfix Bundle，在执行 Test3 core 前把文本 `{0,250000}` 改为 `*`，从而形成原语义对应的 `([\s\S]*?)` 惰性匹配。
- Test3 的二级路由、详情、播放、搜索、漫画/写真解析功能全部继续保留。

## 回归要求
后续新增以下解析能力时必须检查本事故：
- 漫画/写真脚本数组；
- 页面内大 JSON；
- `<script>` 中播放器配置；
- 长 HTML 区段截取；
- packed JS / 大型配置对象。
