## 1.2.1-test.21 / Build 2026092241 — 当前目录搜索 + 最近播放安全携带

用户要求继续按规划优化。当前最近一次明确实机通过基线仍为 Test19；Test20 的“最近播放安全重构”尚未单独收到实机结论，因此 Test21 不把 Test20 标记为已验证，而是从已验证 Test17 `file_manage_v9.js` 不可变基线重新构建文件管理，同时携带 Test20 的小型 `115PlayStore / 115PlayHistory` 模块，并新增独立当前目录搜索页。

### 当前目录搜索

新增：

- `apps/cloud/pan115/modules/folder_search_v1.js`
- 文件管理顶部新增紧凑 `🔎 搜索` 入口；
- 输入框保持短提示，只显示“搜索”，不塞协议/教程文字；
- 只搜索当前这一层目录，不递归进入子目录；
- 不触碰 Test9 以来已经实机证明脆弱但可用的全盘 `115Search` 请求链；
- 直接复用当前文件管理已经稳定使用的 `client.getFiles(cid, ...)`；
- 每次显式搜索最多顺序读取 `5 × 100 = 500` 项；
- 如果当前 500 项扫描满且目录可能还有后续内容，显示“继续扫描”，由用户主动进入下一批；
- 结果中的文件夹可以直接打开，视频可以播放，其它文件可进入文件信息。

这是一种有意的安全折中：宁可“分批、显式继续”，也不为了搜索一个大目录一次性高频扫描数千项，更不恢复后台并发或轮询。

状态：`pending-device-validation-folder-search-and-recent-play`。

2. 文件管理出现 `🔎 搜索`，输入框保持短提示；

## 1.2.1-test.19 / Build 2026092239 — 文件管理 JS 编译错误紧急修复（已实机验证）

用户实机覆盖 Test18 后，打开“文件管理”立即报错：

```text
解析失败！JS编译出错：在属性列表的后面缺少 “}”（JSEngine#68）
```

复核 Test18 安装器确认，问题来自“最近播放 / 视频收藏”阶段对 `115FileManage` 进行**运行时源码字符串注入**。其中视频收藏 `longClick` 代码的对象/属性闭合不平衡，导致整个文件管理页面在 JS 编译阶段失败，属于发布前静态语法校验缺失造成的回归。

Test19 不继续在故障代码上打补丁，而是先恢复稳定边界：

- `115FileManage` **完整恢复到用户已确认正常的 Test17 `file_manage_v9.js`**；
- 保留独立 `115PlayHistory` 页面模块；
- 暂时撤销“文件管理播放时自动记录历史”和“文件长按收藏视频”的注入钩子；
- 搜索、离线中心、账号中心、回收站、登录、磁链 focusMode、文件操作协议全部不动。

用户实机确认：**覆盖 Test19 后文件管理恢复正常。**

长期禁用项：**稳定页面不得再通过多段字符串 `replace/slice` 拼接复杂 JS 属性/长按对象后直接发布。复杂功能必须缩小注入面，并增加发布前和安装时语法解析门禁。**

状态：`device-validated-hotfix`。

## 长期协议与禁用项

外部磁链固定：

```js
function playBy115(url) {
    if (!url) return "toast://未获取到磁力链接";
    return "hiker://page/115Offline?rule=115.简&page=fypage&add=" + encodeURIComponent(url);
}
```

永久禁止/避免：

- magnet → `115Search?kw=`；
- 自行重写完整 115 magnet 协议层；
- 后台高频/并发轮询；
- 普通删除猜 `client.request()` 参数顺序；
- 重写 Test9 已恢复并实机证明工作的搜索请求链；
- 点击目录后另发猜测搜索恢复 ID；
- 把 `fileId` 固定解释为普通文件 ID；
- 普通页面常驻 Cookie/CID/hash/endpoint 等技术字段；
- 通过字符串拼接/替换复杂页面 JS 后未经语法校验直接发布；
- 未经实机验证就标记完整 `deviceValidated`。
