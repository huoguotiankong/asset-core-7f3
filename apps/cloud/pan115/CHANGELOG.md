## 1.2.0-test.8 / Build 2026092209 — 单线程低频磁链状态页

Test7 实机发生严重回归后，用户覆盖回 Test6 并确认“我的文件恢复了”。这进一步确认：Test7 的多任务后台轮询是导致 115 接口异常的重要触发因素，而不是账号文件丢失、登录失效或 Stable 文件浏览逻辑本身损坏。

Test8 必须以 Test6 为唯一安全基线，只改 `115Offline` 外部磁链聚焦页，不修改登录、Cookie、我的文件、普通文件列表、搜索、分享、播放器等公共能力。

安全边界固定为：

```text
并发状态 worker：1
每次 listOfflineTask：只查第 1 页
新磁链：提交前查 1 次
提交后：最多低频确认 2 次（约 1.4s、再约 3.2s）
确认窗口结束：立即停止自动请求
未完成：提示稍后手动确认，不持续轮询
```

实现：

- 首屏立即显示磁链任务卡，不阻塞页面；
- 只有一个 `batchExecute` task，task 内串行完成查重/提交/有限确认；
- 不再创建 Test7 的 8 个并发轮询任务；
- 已完成或出现 `fileId` 时写入当前磁链 ready cache，并仅自动刷新当前聚焦页一次；
- 刷新后直接复用 Test6 的 `appendFastResultItems()` 展开目录/视频，播放继续走 Stable `115Api.player.resolve()`；
- 如果短时确认窗口内仍未完成，页面停止自动访问 115，只保留“手动确认状态”和“全部离线任务”；
- 手动确认按钮不再返回 `false`，避免海阔弹出 `未知链接：false`；
- 保存目录仍执行 `根目录/海阔视界 → 云下载/离线下载 → 根目录`；
- 程序名固定 `115.简`，同名覆盖并复用登录状态。

实机验收优先级：

1. 导入后先进入“我的文件”，必须继续正常显示；
2. 用一个未离线过的新 magnet 测试，磁链页应立即出现；
3. 测试期间“我的文件”和普通文件浏览不得变空；
4. “全部离线任务”不得再出现 `接口返回非JSON / <!doctype html>`；
5. 快速完成的任务应在有限确认窗口内自动进入文件/视频；
6. 未快速完成时应停止自动请求，不得持续后台轮询；
7. 新任务仍应进入根目录 `海阔视界`。

当前状态：`active-test-safe-single-flight-pending-device-validation`。

## 1.2.0-test.7 / Build 2026092208 — 禁用：高频动态任务页事故版

最初根据 `FNS-252` 的实机证据，尝试用 `batchExecute + updateItem` 做迅雷式动态任务页。方向上的判断成立：该案例中 115 后台已经完成，而聚焦页仍停在“正在连接115”，说明页面状态传播确实存在明显延迟。

但 Test7 的实现方式错误：一次外部 magnet 会同时创建 8 个错峰后台任务，每个任务最多再查询 1～2 页离线任务。实机随后出现：

```text
磁链聚焦页：一直停在“正在提交到115”
全部离线任务：接口返回非 JSON，实际返回 <!doctype html>...
我的文件：直接空白
```

用户覆盖回 Test6 后明确确认“我的文件恢复了”。因此 Test7 被判定为禁用方案：115 接口对这种高并发状态查询不够容忍，可能触发风控/会话异常或临时返回 HTML。以后 115 状态跟踪禁止使用多路并发轮询。

禁止恢复：

- 8 路或类似数量的并发 115 状态查询；
- 连续多页任务列表轮询；
- 为了“实时”而长期后台访问 115；
- 任何会影响“我的文件”/普通网盘公共请求稳定性的状态跟踪设计。

当前状态：`disabled-regression-do-not-reuse`。

## 1.2.0-test.1 / Build 2026092202 — 云下载目录 + 快速离线结果

用户实机继续反馈 Stable 1.1.0 两个体验问题：

1. 外部 magnet 提交后经常需要手动刷新多次，才能看到任务完成或进入结果；
2. 新离线任务默认落在网盘根目录，而不是 115 自己的“云下载”目录。

源码恢复确认根因：Stable 1.1.0 的 `115Offline` 在外部 magnet、失败重试、手工添加三条链上都把 `addOfflineTaskURIs(..., "0")` 写死，`"0"` 即根目录；新任务提交后也只立即查一次任务列表，没有短时自动追踪，所以 115 后端稍有最终一致性延迟就需要用户手动刷新。

Test 1.2.0-test.1 只覆盖 `115Offline`，Stable 1.1.0 保持不动：

- 优先调用 115 `get_id` 能力读取 canonical 云下载目录，取返回的 `dest_cid` 作为离线 `wp_path_id`；
- 云下载 CID 会本地缓存，并在后续进入离线页时通过当前 115 Client 校验；
- 官方目录解析失败时，仅尝试复用根目录中已存在的“云下载/离线下载”目录；仍失败才临时回退根目录，并在 Test 页面显式提示，便于实机反馈；
- 外部 magnet 提交后进行有上限的短时轮询，不做无限阻塞；
- `fileId` 一旦出现就视为“结果已开始可用”的提前信号，不再只等 `status === 2`；
- 当前磁链页会直接展开任务结果目录中的文件夹和视频；视频点击继续复用原版 `115Api.player.resolve()`；
- 保留 Stable 1.1.0 的 BTIH/URL 查重、结果缓存、失败重试、主片直放、多集选集逻辑；
- 不修改登录/Cookie/扫码、m115 加解密、115 分享、普通网盘文件列表与搜索、直链播放器。

实机验收重点：

1. 用一个未缓存的新 magnet 从 JavDB/磁力君等入口调用 `115Offline?add=`；
2. 页面应显示“☁ 保存到 115 云下载”及实际 CID，而不是根目录回退警告；
3. 新任务出现/返回 `fileId` 后，不应再依赖连续手动刷新多次；
4. 当前页应尽快出现 `📂` 结果目录和 `▶` 视频项，点击视频可直接播放；
5. 115 网盘实际文件位置应位于云下载目录；
6. 重复调用同一 magnet 仍应查重，不产生重复离线任务。

当前状态：`superseded-by-1.2.0-test.8`。

## 基线与协议事实

基线来自用户上传的 `115.简.hk小程序.zip`，原规则为单文件 `rule.json`。原实现已具备：

- 115 Cookie / 扫码登录；
- 文件列表与全盘搜索；
- 115 分享；
- 离线任务；
- `magnet / ed2k / http(s)` 离线添加；
- 个人网盘文件直链解析与播放。

已确认：

- `addOfflineTaskURIs()` 使用 `https://lixian.115.com/lixianssp/?ac=add_task_urls`；
- `listOfflineTask()` 的 `file_id` 映射为任务结果 `fileId`；
- `wp_path_id` 映射为 `dirId`，它是任务结果的父目录；
- 原 `player.resolve()` 能通过 pickcode / fileId 取得 115 直链并带 UA/Header 播放。

## 对外磁链调用协议

其它小程序调用 115 播放 magnet 的正式入口固定为：

```js
"hiker://page/115Offline?rule=115.简&page=fypage&add=" + encodeURIComponent(url)
```

原版旧“复制调用”里的：

```js
"hiker://page/115Search?rule=115.简&page=fypage&kw=" + encodeURIComponent(url)
```

**禁止用于 magnet。** 用户实机已证明它只会把整条 magnet 当普通网盘搜索关键词，结果为 `共0条 / 无结果`。

首页真实输入分流：

```text
115 分享链接
→ 115Share?sc=

magnet / ed2k / HTTP(S)
→ 115Offline?add=

普通关键词
→ 115Search?kw=
```

## Stable 1.1.0 磁链播放链

```text
其它小程序传 magnet
→ 115Offline?add=
→ BTIH / URL 查重
→ 当前任务聚焦
→ 已存在则复用，不重复离线
→ 新任务才提交到 115 离线
→ 完成后优先 task.fileId
→ fileId 是视频：直接进入原版 player.resolve
→ fileId 是目录：受控扫描视频
→ 过滤 sample / preview / trailer / 试看 / 预告 / 花絮 / 广告等噪声
→ 单一明显主片：直接播放
→ 多集 / 多段：进入 115OfflineResult 选集
→ 播放结果缓存复用
```

扫描边界：最多递归 4 层、最多约 500 项，避免大目录拖死页面。

### 原版完成任务问题


## 后续其它小程序接入规范

其它带 magnet 的小程序只依赖这一条稳定契约：

```js
function playBy115(url) {
    if (!url) return "toast://未获取到磁力链接";
    return "hiker://page/115Offline?rule=115.简&page=fypage&add=" + encodeURIComponent(url);
}
```

调用方不得直接依赖 115Api、fileId、离线接口或播放器内部实现。115 内部以后升级时必须继续兼容 `115Offline?add=`，避免批量修改所有上游小程序。
