# Hanime1 Changelog

> 程序级长期技术记忆。后续开发/优化本程序前，先读三份全局文档，再读本文件、registry 和当前运行入口。已验证事实与待实机验证内容必须分开记录。

## 当前基线
- Legacy：`1.2.1` 仅保留历史记录，不再作为开发运行基线。
- Test：`2.0.0-test.9` / Build `20009` / Shell `2026082218`。
- 产品方向：Han1mePlus/APK 主要用于研究 Cloudflare、Cookie、登录和官网协议；海阔实现以“验证后直接读取官网”为主，不追求 APK 像素级复刻。

## 已验证实机事实
- Test6：首页 Banner/卡片封面恢复；默认最高画质播放实机通过；漫画首页可获取；评论真实数据可读。
- Test7：公开片库无需登录可用；播放继续 1080 优先；评论可读取数百条真实数据。
- Test8：用户确认官网预告页本身当前也异常；片库筛选交互过于间接；视频详情标签会先进入筛选配置页而不是直接结果；漫画分类方向较好但仍需美化；X5 官网登录依旧无法正常完成账号链。

## 长期会话/验证架构
- WebView 仅负责 Cloudflare Challenge 与必要网页兜底；正常业务请求直接 fetch 官网。
- 视频站与漫画站按 Origin 独立验证；账号 Cookie 与 `cf_clearance` 分离。
- 交互式 Turnstile/验证码不能承诺无人值守，必须保留可见 WebView 兜底。
- 海阔 fetch 会自动管理 Set-Cookie；账号表单优先利用这一原生 Cookie Jar，而不是依赖外部 X5 回传 Cookie。

## Test9：点即结果 + 原生账号登录
### 筛选交互
- 片库不再要求先进入“专业筛选”页配置条件。
- 片库顶部固定：类型 / 排序 / 日期 / 时长 / 标签 / 全部分类 / 清除。
- 类型、排序、日期、时长、常用标签使用 `select://` 弹层；选择后立即 `refreshPage(false)`，结果直接出现在下方。
- 常用标签提供可直接切换的流式 Chip；组合筛选继续保留官网 canonical search_key。
- `hanimeVideoFilter` 重新定义为“分类目录”：点击任意类型/排序/日期/时长/完整标签后直接进入结果，不再存在“选择后还要应用”的中间状态。
- 新增 `hanimeVideoResults`，供详情标签与分类目录直接打开结果。

### 视频详情
- 标签点击直接进入 `hanimeVideoResults?tag=...`，不再先进入筛选页。
- 作品信息、标签、简介、可用画质、相关推荐分区重新排版。
- 已实机通过的最高画质优先播放链不变。

### 漫画
- 漫画分类继续沿用 HanimeOne 官方标签/作者/角色/同人/社团/语言/分类目录。
- 分类页改流式主分类 + 双列目录；漫画列表增加分类返回与分页；详情元信息/分组标签继续使用真实官方 path 直达结果。

### 登录
- Test7/8 的 X5 官网登录后 Cookie 同步已由实机证明不可靠，Test9 不再把它作为主登录方案。
- 主登录改为：GET `/login` → 解析 `_token` / `csrf-token` → POST `/login`，字段 `email/password/_token/remember`。
- 登录成功后通过 `profile()` 再校验账号并保存为受管账号；账号 Cookie 与 `cf_clearance` 继续分离。
- 邮箱保留在临时 MyVar；密码仅存临时 MyVar，提交后无论成功/失败都立即清除。
- 保留“粘贴 Cookie 登录”兜底：直接用用户提供的已登录 Cookie 读取首页和 `/user/<id>/edit`，成功后存为受管账号。
- X5 官网登录仅保留备用入口，不再依赖其 Cookie 回传。
- **Test9 原生表单登录尚需海阔实机验证，未验证前不能写入跨程序通用指南。**

### 预告
- 用户已确认 Hanime1 官网当前预告页本身异常。
- Test9 不再自动轮询多主站/外部数据源把上游 500 包装成“解析失败”；页面明确显示“上游暂不可用”，并保留打开官网入口。
- 官网恢复后再重新启用原生预告链。

### 评论/UI
- 评论/回复改 `rich_text`：用户名、时间、回复数与正文分层显示，25 条分页，取消无头像占位。
- 视频/漫画详情继续使用原生 Hero + 信息 Chip + 长文本简介 + 三列相关推荐，统一视觉层次。

## 禁止回退方案
- 不猜测筛选参数；始终以官网 canonical search_key 为准。
- 不让普通筛选进入“配置→应用→结果”的三段式流程；普通筛选必须点即结果。
- 不让详情标签跳到筛选配置页；标签必须直接进入结果。
- 不再把 X5 Cookie 同步作为账号主登录链。
- 不把官网自身 5xx 当成本程序解析故障反复重试。
- 不破坏已通过实机验证的最高画质优先播放和 signed cover 链。
